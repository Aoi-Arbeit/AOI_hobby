## 1. プロジェクト概要

### 1.1 プロジェクト名

じゃんけんゲーム Web アプリケーション（Rock Paper Scissors Game）

### 1.2 目的

本プロジェクトは、Web アプリケーション開発の学習を目的として、ブラウザ上で動作するじゃんけんゲームを作成するものである。HTML / CSS / JavaScript の基本的な使い方を実践を通じて習得し、フロントエンド開発の基礎知識を身につけることを目指す。

### 1.3 背景

Web アプリケーション開発を学ぶにあたり、実際に動くアプリを作ることが最も効果的な学習方法の一つである。じゃんけんゲームは、ゲームロジック・UI 更新・イベント処理など、Web アプリ開発に必要な基本要素を包括的に学べるテーマとして適している。

### 1.4 スコープ

| 区分 | 内容 |
|------|------|
| 対象 | ブラウザで動作するフロントエンドのみ（サーバー・データベースなし） |
| 除外 | ユーザー認証、オンライン対戦、データの永続保存、スマートフォンアプリ |
| 開発者 | いずき（個人開発） |

## 2. ユーザー要件

### 2.1 ターゲットユーザー

- **主要ユーザー：** 開発者自身（いずき）
- **利用目的：** 学習成果の確認・ゲームプレイ
- **利用環境：** PC の Web ブラウザ

### 2.2 ユーザーストーリー

| No. | ユーザーストーリー | 受け入れ条件 |
|-----|--------------------|-------------|
| US-1 | ユーザーとして、グー・チョキ・パーのいずれかを選択できる | ボタンが 3 つ表示され、クリックで選択できること |
| US-2 | ユーザーとして、コンピューターが自動でじゃんけんを出す様子を見たい | コンピューターの選択がランダムで決定・表示されること |
| US-3 | ユーザーとして、勝敗結果をすぐに確認したい | 勝ち・負け・引き分けが日本語で表示されること |
| US-4 | ユーザーとして、今までの勝敗数を把握したい | 累計の勝・負・引き分け回数が表示されること |
| US-5 | ユーザーとして、連勝・連敗がどれだけ続いているか知りたい | 現在の連勝数または連敗数がリアルタイムで表示されること |
| US-6 | ユーザーとして、ゲームをリセットして最初からやり直したい | リセットボタン押下でスコアと記録がすべて初期化されること |

## 3. 機能要件

### 3.1 機能一覧

| 機能 ID | 機能名 | 説明 |
|---------|--------|------|
| F-01 | 手の選択 | グー・チョキ・パーの 3 つのボタンを表示し、ユーザーが選択できる |
| F-02 | コンピューター手決定 | ユーザーが選択後、コンピューターがランダムで手を決定する |
| F-03 | 勝敗判定 | ユーザーとコンピューターの手を比較し、勝敗を判定・表示する |
| F-04 | スコア記録 | 累計の勝・負・引き分け回数をカウントして画面に表示する |
| F-05 | 連勝・連敗カウント | 現在の連勝数または連敗数を計算・表示する |
| F-06 | ゲームリセット | スコアおよび連勝・連敗カウントを初期値（0）に戻す |

### 3.2 機能詳細

#### F-01　手の選択

- グー・チョキ・パーの 3 つのボタンを画面に表示する
- 各ボタンには絵文字（✊ ✌️ ✋）と文字ラベルを表示する
- ボタン押下でユーザーの選択を確定する
- 選択中のボタンを視覚的に強調表示する（ハイライトなど）

#### F-02　コンピューター手決定

- ユーザーが手を選択したタイミングで、コンピューターがランダムに手を決定する
- 乱数は JavaScript の `Math.random()` を使用する
- コンピューターの選択結果を画面上に表示する

#### F-03　勝敗判定

以下のルールに従い勝敗を判定する。

| ユーザー | コンピューター | 結果 |
|----------|----------------|------|
| グー | チョキ | ユーザー勝ち |
| チョキ | パー | ユーザー勝ち |
| パー | グー | ユーザー勝ち |
| 同じ手 | 同じ手 | 引き分け |
| 上記以外 | — | ユーザー負け |

- 結果を「あなたの勝ち！」「あなたの負け…」「引き分け」として画面に表示する
- 結果に応じてメッセージの色を変える（勝ち：青系、負け：赤系、引き分け：グレー系）

#### F-04　スコア記録

- ゲームのたびに勝・負・引き分けのカウントを更新する
- 画面上に「勝：N 回 / 負：N 回 / 引き分け：N 回」の形式で表示する
- ページをリロードするとスコアはリセットされる（データの永続化なし）

#### F-05　連勝・連敗カウント

- 勝ちが続いた場合は「連勝中：N 連勝」と表示する
- 負けが続いた場合は「連敗中：N 連敗」と表示する
- 引き分けの場合、連勝・連敗カウントはリセットされる
- 勝ちから負け（またはその逆）に変わった場合もカウントをリセットする

#### F-06　ゲームリセット

- 「リセット」ボタンを画面に配置する
- 押下すると以下の値をすべて初期化する
  - 勝・負・引き分けのカウント → 0
  - 連勝・連敗カウント → 0
  - 結果表示メッセージ → デフォルトメッセージ
  - ユーザー・コンピューターの手の表示 → 初期状態

## 4. 非機能要件

### 4.1 パフォーマンス

| 項目 | 要件 |
|------|------|
| 画面表示速度 | ブラウザでファイルを開いた後、2 秒以内に表示が完了すること |
| 操作レスポンス | ボタン押下から結果表示まで 0.5 秒以内に完了すること |
| 外部依存 | 外部 API やサーバーへの通信が不要であること（オフラインで動作） |

### 4.2 互換性

| 項目 | 要件 |
|------|------|
| 対応ブラウザ | Google Chrome（最新版） |
| 対応デバイス | PC（デスクトップ・ラップトップ） |
| 画面解像度 | 横幅 1024px 以上を基本とする |

### 4.3 保守性

| 項目 | 要件 |
|------|------|
| ファイル構成 | HTML・CSS・JavaScript をそれぞれ別ファイルに分離すること |
| コードの可読性 | 変数名・関数名は意味がわかる名前をつけること（日本語コメントを推奨） |
| 外部ライブラリ | 学習目的のため、原則バニラ JavaScript（ライブラリなし）で実装すること |

### 4.4 ユーザビリティ

| 項目 | 要件 |
|------|------|
| デザイン | ポップ・カラフルな配色で楽しい雰囲気を演出すること |
| 操作性 | マウスのクリックのみで全操作が完結すること |
| 視認性 | ボタンやテキストが読みやすく、重要情報が一目でわかるレイアウトにすること |
| フィードバック | ユーザーの操作に対して視覚的なフィードバックを即時に提供すること |

## 5. 制約条件

| No. | 制約項目 | 内容 |
|-----|----------|------|
| C-01 | 技術スタック | HTML / CSS / JavaScript（バニラ）のみを使用する。フレームワーク・ライブラリは使用しない |
| C-02 | サーバー不要 | サーバーサイドの処理なし。すべてクライアントサイド（ブラウザ内）で動作する |
| C-03 | データ保存なし | データベースや localStorage による永続化は行わない。ページリロードでリセットされる |
| C-04 | 開発環境 | テキストエディタ（VSCode 等）とブラウザのみで開発可能な構成とする |
| C-05 | 学習目的 | あくまで学習用途であり、外部公開・商用利用は想定しない |

## 6. 用語定義

| 用語 | 定義 |
|------|------|
| Web アプリケーション | Web ブラウザ上で動作するアプリケーション。本プロジェクトでは HTML ファイルをブラウザで開くことで動作する |
| フロントエンド | ユーザーが直接操作する画面側の処理。HTML・CSS・JavaScript で実装される |
| バニラ JavaScript | フレームワークやライブラリを使わない、素の JavaScript のこと |
| 連勝 | 同じユーザーが連続して勝利すること。引き分けまたは敗北でリセットされる |
| 連敗 | 同じユーザーが連続して敗北すること。引き分けまたは勝利でリセットされる |
| リセット | すべてのスコア・カウントを初期値（0）に戻すこと |
