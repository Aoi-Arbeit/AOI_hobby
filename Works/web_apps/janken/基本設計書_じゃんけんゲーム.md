## 1. システム構成

### 1.1 全体アーキテクチャ

本アプリはサーバーを使わず、ブラウザだけで完結する **シングルページアプリケーション（SPA）** として構成する。

```
[ ユーザー ]
     |
     | ブラウザで index.html を開く
     v
+---------------------+
|      ブラウザ        |
|                     |
|  index.html  ←── style.css
|      |              |
|      └──────────── script.js
|                     |
|  ※ サーバー通信なし  |
|  ※ すべてローカル動作 |
+---------------------+
```

### 1.2 動作環境

| 項目 | 内容 |
|------|------|
| 実行環境 | Web ブラウザ（Google Chrome 最新版） |
| サーバー | 不要（ローカルファイルをそのまま開く） |
| インターネット接続 | 不要（完全オフライン動作） |
| データ永続化 | なし（ページリロードでリセット） |

## 2. ファイル構成

```
janken-game/          ← プロジェクトフォルダ
├── index.html        ← 画面の骨格（HTML）
├── style.css         ← デザイン・レイアウト（CSS）
└── script.js         ← ゲームロジック・イベント処理（JavaScript）
```

### 各ファイルの役割

| ファイル | 役割 |
|----------|------|
| `index.html` | 画面の構造を定義する。ボタン・テキスト・スコア表示エリアなどを記述する |
| `style.css` | 色・フォント・レイアウト・アニメーションなどの見た目を定義する |
| `script.js` | じゃんけんのロジック、スコア計算、画面の更新処理を記述する |

## 3. 画面設計

### 3.1 画面一覧

本アプリは画面が **1 つのみ** のシングルページ構成とする。

| 画面 ID | 画面名 | 説明 |
|---------|--------|------|
| SCR-01 | ゲームメイン画面 | じゃんけんの全操作を行う唯一の画面 |

### 3.2 画面レイアウト（ワイヤーフレーム）

```
+------------------------------------------------+
|          🎮 じゃんけんゲーム                    |  ← タイトル
+------------------------------------------------+
|                                                |
|   [ スコア表示エリア ]                          |
|   勝: 0 回　|　負: 0 回　|　引き分け: 0 回      |
|                                                |
|   [ 連勝・連敗表示エリア ]                      |
|   🔥 連勝中: 0 連勝                            |
|                                                |
+------------------------------------------------+
|                                                |
|   あなたの手        コンピューターの手           |
|      ❓                    ❓                  |
|                                                |
|   [ 結果表示エリア ]                            |
|        ここに結果が表示されます                  |
|                                                |
+------------------------------------------------+
|                                                |
|   [ 手を選ぶボタン ]                            |
|                                                |
|   [✊ グー]  [✌️ チョキ]  [✋ パー]            |
|                                                |
+------------------------------------------------+
|          [ 🔄 リセット ]                        |  ← リセットボタン
+------------------------------------------------+
```

### 3.3 UI コンポーネント一覧

| コンポーネント ID | 名称 | 種別 | 説明 |
|-----------------|------|------|------|
| UI-01 | タイトル | テキスト | アプリ名を表示する見出し |
| UI-02 | スコア表示エリア | テキスト | 勝・負・引き分けの累計回数を表示 |
| UI-03 | 連勝・連敗表示 | テキスト | 現在の連勝数または連敗数を表示 |
| UI-04 | ユーザーの手表示 | テキスト（絵文字） | ユーザーが選んだ手を絵文字で表示 |
| UI-05 | コンピューターの手表示 | テキスト（絵文字） | コンピューターの手を絵文字で表示 |
| UI-06 | 結果表示エリア | テキスト | 勝敗結果メッセージを表示 |
| UI-07 | グーボタン | ボタン | グーを選択する |
| UI-08 | チョキボタン | ボタン | チョキを選択する |
| UI-09 | パーボタン | ボタン | パーを選択する |
| UI-10 | リセットボタン | ボタン | ゲームをリセットする |

### 3.4 デザイン方針

| 項目 | 方針 |
|------|------|
| カラーテーマ | ポップ・カラフル。背景は明るい色（グラデーション可）、ボタンは鮮やかな色 |
| フォント | 丸みのある見やすいフォント（例：`'Rounded Mplus 1c'` または Web 標準フォント） |
| ボタンサイズ | タップ・クリックしやすい大きめのサイズ（最低 80px × 80px 程度） |
| アニメーション | ボタン押下時に軽いスケールアニメーション（`transform: scale`）を付与 |
| 結果カラー | 勝ち：青系（`#3B82F6`）、負け：赤系（`#EF4444`）、引き分け：グレー（`#6B7280`） |

## 4. 処理フロー設計

### 4.1 メイン処理フロー（じゃんけん 1 回分）

```
ユーザーがボタンをクリック（グー / チョキ / パー）
         |
         v
ユーザーの選択を取得・表示（UI-04 更新）
         |
         v
コンピューターの手をランダムに決定（0〜2 の乱数）
         |
         v
コンピューターの手を表示（UI-05 更新）
         |
         v
勝敗判定ロジックを実行
         |
    +----+----+----+
    |         |    |
   勝ち      負け  引き分け
    |         |    |
    v         v    v
スコア更新（勝 +1 / 負 +1 / 引き分け +1）
         |
         v
連勝・連敗カウント更新
    ・勝ち → 連勝 +1、連敗をリセット
    ・負け → 連敗 +1、連勝をリセット
    ・引き分け → 連勝・連敗ともリセット
         |
         v
画面を更新（スコア・連勝連敗・結果メッセージ）
         |
         v
次のクリックを待つ（待機状態）
```

### 4.2 リセット処理フロー

```
リセットボタンをクリック
         |
         v
全変数を初期値（0）にリセット
         |
         v
画面表示を初期状態に戻す
    ・スコア表示 → すべて 0
    ・連勝・連敗 → 0
    ・手の表示  → ❓
    ・結果メッセージ → デフォルトテキスト
         |
         v
待機状態へ
```

### 4.3 勝敗判定ロジック

グー = `0`、チョキ = `1`、パー = `2` と定義し、以下の表で判定する。

| ユーザー | コンピューター | 判定式 | 結果 |
|----------|----------------|--------|------|
| グー（0） | チョキ（1） | user === 0 && cpu === 1 | 勝ち |
| チョキ（1） | パー（2） | user === 1 && cpu === 2 | 勝ち |
| パー（2） | グー（0） | user === 2 && cpu === 0 | 勝ち |
| 同じ | 同じ | user === cpu | 引き分け |
| 上記以外 | — | — | 負け |

> **実装のポイント：** `(user - cpu + 3) % 3 === 1` が `true` なら勝ち、`=== 0` なら引き分け、`=== 2` なら負けと一行で判定することもできる（詳細設計で説明）。

## 5. 状態（データ）設計

### 5.1 アプリが保持する状態一覧

JavaScript の変数として管理するデータを定義する。

| 変数名 | データ型 | 初期値 | 説明 |
|--------|----------|--------|------|
| `winCount` | 数値（Number） | `0` | 勝利回数 |
| `loseCount` | 数値（Number） | `0` | 敗北回数 |
| `drawCount` | 数値（Number） | `0` | 引き分け回数 |
| `winStreak` | 数値（Number） | `0` | 現在の連勝数 |
| `loseStreak` | 数値（Number） | `0` | 現在の連敗数 |

### 5.2 手の定義

コード内で手を数値で扱い、表示時に変換する。

| 数値 | 手 | 絵文字 | 文字列 |
|------|----|--------|--------|
| `0` | グー | ✊ | `"グー"` |
| `1` | チョキ | ✌️ | `"チョキ"` |
| `2` | パー | ✋ | `"パー"` |

## 6. 使用技術

### 6.1 技術スタック

| 分類 | 技術 | バージョン | 用途 |
|------|------|-----------|------|
| マークアップ | HTML | 5 | 画面の骨格定義 |
| スタイリング | CSS | 3 | レイアウト・デザイン |
| プログラミング | JavaScript | ES6+ | ゲームロジック・DOM 操作 |

### 6.2 主要な JavaScript 機能

| 機能 | 使用する API / 構文 | 用途 |
|------|---------------------|------|
| 乱数生成 | `Math.random()` / `Math.floor()` | コンピューターの手をランダムに決定 |
| DOM 取得 | `document.getElementById()` | HTML 要素を取得して操作 |
| テキスト更新 | `element.textContent` | 結果・スコアの表示更新 |
| クラス操作 | `element.classList` | 結果に応じた色変更 |
| イベント処理 | `addEventListener('click', ...)` | ボタンのクリック検知 |

### 6.3 CSS 技術

| 技術 | 用途 |
|------|------|
| Flexbox | ボタンや表示エリアの横並びレイアウト |
| CSS Variables（カスタムプロパティ） | テーマカラーの一元管理 |
| `transition` / `transform` | ボタン押下アニメーション |
| `@keyframes` | 結果表示のフェードインアニメーション（任意） |
