1プロジェクト概要
1.1 目的

ブラウザ上で報告書・企画書などのビジネス文書を作成し、デバイスや環境に依存しない一貫したレイアウトで PDF（A4サイズ）として出力できるWebアプリケーションを構築する。

1.2 背景・課題
  • 既存のWord / Google ドキュメントではブラウザ印刷時にフォント・余白がデバイスによってずれる。
  • ピクセル単位の絶対座標管理により、どのデバイスでも同一の印刷結果を保証したい。
  • 外部サーバー不要で動作する軽量な Vanilla JS ベースの実装が求められる。

3絶対座標管理とレイアウト設計
3.1 座標系の定義

すべての要素はA4用紙を基準とした論理座標（単位: mm）で定義する。 ブラウザのdpr（デバイスピクセル比）やウィンドウ幅に左右されないよう、 レンダリング時に「mm → px」変換を一元管理するユーティリティ関数を設ける。

js/utils/coords.js
const DPI = 96; const MM_PER_INCH = 25.4; export const mmToPx = (mm) => mm / MM_PER_INCH * DPI; // A4 = 210mm × 297mm → 794px × 1123px (96dpi) export const A4_W_PX = mmToPx(210); // ≈ 794px export const A4_H_PX = mmToPx(297); // ≈ 1123px

3.3 デバイス間差異の排除方針
  • プレビュー用コンテナは常に 794px × 1123px の固定サイズで描画し、CSS transform: scale() でビューポートに収める。
  • フォントはWebフォント（Noto CJK）で統一し、システムフォントに依存しない。
  • 行高・文字間隔はmmまたはpt単位で指定し、相対単位（em / rem）を使用しない。
  • PDF生成ライブラリには座標をmm単位で直接渡し、ブラウザのレンダリングを経由しない経路も確保する。
css/a4-canvas.css — A4固定キャンバス
/* A4 キャンバス固定サイズ */ .a4-canvas { position: relative; width: 794px; /* mmToPx(210) */ height: 1123px; /* mmToPx(297) */ background: #fff; overflow: hidden; } /* ビューポートに合わせてスケール */ .a4-wrapper { transform-origin: top center; transform: scale(var(--canvas-scale)); }
