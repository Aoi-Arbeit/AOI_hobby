## 1. 注文エンジン詳細設計

### 1.1 注文ステートマシン（状態遷移図）

すべての注文は以下の状態を遷移する。状態変更はすべてDBトランザクション内で行い、中間状態の不整合を防ぐ。

```
                    ┌─────────────────────────────────────────────────┐
                    │               注文ライフサイクル                   │
                    └─────────────────────────────────────────────────┘

  [発注]
    │
    ▼
┌──────────┐   証拠金不足 / バリデーションエラー
│ PENDING  │─────────────────────────────────────► [REJECTED]
│（未約定）  │
└──────────┘
    │
    │ ────────────────────────────────────────────────────────────────
    │  成行注文（market）                指値・逆指値・OCO・IFD・IFO
    │  ↓ 即時処理                        ↓ 注文エンジンのキューに積む
    │                                    ↓ 条件監視ループに入る
    │
    ▼ （成行）                  ┌──────────────────────────┐
┌──────────┐                   │  OPEN（監視中）            │
│ FILLING  │                   │  Celery Worker が         │
│（約定処理中）│                  │  1秒間隔でレートチェック     │
└──────────┘                   └───────────┬──────────────┘
    │                                       │
    │ スリッページ計算                        │ 条件合致（レート到達）
    │ DB書き込み（トランザクション）           │
    │                                       ▼
    │                          ┌──────────────────────────┐
    │                          │  FILLING（約定処理中）      │
    │                          │  Redlock 取得             │
    │                          │  スリッページ計算            │
    │                          │  DB書き込み               │
    │                          └──────────────────────────┘
    │                                       │
    ▼                                       │
┌──────────┐ ◄─────────────────────────────┘
│  FILLED  │
│（約定済み）│────────────────────────────► position 生成
└──────────┘
    │  OCO の場合: 対注文を CANCELLED に
    │  IFD/IFO の場合: 次段の注文を OPEN に
    │
    │  ユーザーがキャンセル操作
    ▼                      ▼
┌──────────┐           ┌──────────┐
│CANCELLED │           │EXPIRED   │
│（取消済み）│           │（期限切れ）│
└──────────┘           └──────────┘
```

#### 注文タイプ別の状態遷移補足

| 注文タイプ | FILLED 後の追加処理 |
|-----------|-------------------|
| `market` | position 生成のみ |
| `limit` | position 生成のみ |
| `stop` | position 生成のみ |
| `oco` | `linked_order_id` の注文を `CANCELLED` に変更（同一トランザクション） |
| `ifd` | `parent_order_id` を持つ次段の注文を `PENDING → OPEN` に変更 |
| `ifo` | IFDと同様に次段（OCO構成のSL/TP注文ペア）を `OPEN` に変更 |

### 1.2 注文エンジンの処理フロー（疑似コード）

```python
# order_engine.py（Celery Periodic Task）

@celery.task
def run_order_matching_cycle():
    """
    1秒間隔で実行。全ユーザーのOPEN注文を一括チェック。
    """
    current_rates = redis.get_all_rates()  # Redisから最新レートを取得

    # OPEN状態の全注文を取得（インデックス: status + symbol）
    open_orders = db.query(
        "SELECT * FROM orders WHERE status = 'open' FOR UPDATE SKIP LOCKED"
    )

    for order in open_orders:
        rate = current_rates[order.symbol]
        if should_fill(order, rate):
            fill_order(order, rate)


def should_fill(order: Order, rate: Rate) -> bool:
    """約定条件の判定"""
    if order.type == 'limit':
        # Buy指値: Ask が指値以下になったら約定
        if order.side == 'buy':
            return rate.ask <= order.limit_price
        # Sell指値: Bid が指値以上になったら約定
        else:
            return rate.bid >= order.limit_price

    elif order.type == 'stop':
        # Buy逆指値: Ask が逆指値以上になったら約定（ブレイクアウト）
        if order.side == 'buy':
            return rate.ask >= order.stop_price
        # Sell逆指値: Bid が逆指値以下になったら約定
        else:
            return rate.bid <= order.stop_price

    elif order.type == 'oco':
        # OCOはlimitとstopの両条件を同時チェック
        return should_fill_limit(order, rate) or should_fill_stop(order, rate)

    return False


def fill_order(order: Order, rate: Rate):
    """
    約定処理。Redlockで同一注文の二重処理を防止。
    """
    lock_key = f"order_lock:{order.id}"

    # Redlockで分散ロック取得（TTL: 5秒）
    with redis.lock(lock_key, timeout=5):

        # ロック取得後に再度ステータスを確認（二重チェック）
        current_order = db.get_order(order.id)
        if current_order.status != 'open':
            return  # 他ワーカーが先に処理済み → スキップ

        # スリッページ計算
        slippage = calculate_slippage(order, rate)
        filled_price = apply_slippage(order, rate, slippage)

        # トランザクション開始
        with db.transaction():
            # 1. 注文を FILLED に更新
            db.update_order(order.id, status='filled',
                            filled_price=filled_price,
                            slippage_pips=slippage,
                            filled_at=now_utc())

            # 2. ポジション生成
            position_id = db.create_position(order, filled_price)

            # 3. 証拠金を拘束（残高から必要証拠金を引く）
            required_margin = calc_required_margin(order, filled_price)
            db.deduct_margin(order.account_id, required_margin)

            # 4. OCO の場合: 対注文をキャンセル
            if order.type == 'oco' and order.linked_order_id:
                db.update_order(order.linked_order_id,
                                status='cancelled',
                                cancelled_at=now_utc())

            # 5. IFD/IFO の場合: 次段の注文を OPEN に
            if order.type in ('ifd', 'ifo'):
                child_orders = db.get_child_orders(order.id)
                for child in child_orders:
                    db.update_order(child.id, status='open')

            # 6. 監査ログ記録
            db.insert_audit_log(user_id=order.user_id,
                                action='order.filled',
                                entity_id=order.id,
                                payload=order.to_dict(),
                                result={'filled_price': filled_price,
                                        'position_id': position_id})

        # 7. WebSocketで約定通知をブロードキャスト
        ws_broadcast(order.user_id, event='order.filled', data={
            'order_id': order.id,
            'filled_price': filled_price,
            'slippage_pips': slippage,
            'position_id': position_id
        })
```

### 1.3 ロスカット判定フロー

```
┌─────────────────────────────────────────────────────────────┐
│              ロスカット判定（毎レート更新時に実行）               │
└─────────────────────────────────────────────────────────────┘

レート更新イベント発生
    │
    ▼
全ユーザーの保有ポジション（status='open'）を対象にループ
    │
    ├── 含み損益を計算
    │   unrealized_pnl = calc_unrealized_pnl(position, current_rate)
    │
    ├── 有効証拠金を計算
    │   equity = balance + SUM(unrealized_pnl for all positions)
    │
    ├── 必要証拠金合計を計算
    │   required_margin_total = SUM(required_margin for all open positions)
    │
    ├── 証拠金維持率を計算
    │   margin_level = equity / required_margin_total * 100
    │
    ├── [SL/TPチェック]
    │   ├── TP到達: fill_order(tp_order, current_rate) → 利確決済
    │   └── SL到達: fill_order(sl_order, current_rate) → 損切り決済
    │
    └── [ロスカットチェック]
        margin_level < 100%（閾値）?
            │
            ├── YES → 全ポジションを強制決済
            │         ・close_reason = 'loss_cut'
            │         ・exit_price = 現在Bid（Buyポジション）/ Ask（Sellポジション）
            │         ・WebSocket: position.loss_cut イベントを送信
            │
            └── NO  → 次のレート更新まで待機
```

#### ロスカット閾値の設計

| 維持率 | 処理 |
|--------|------|
| 200%以上 | 正常 |
| 100〜199% | 警告トースト表示（フロントエンド） |
| 100%未満 | ロスカット発動（全ポジション強制決済） |

> **設計根拠**: 実際の国内FX業者はおおむね維持率100%でロスカット。追証なし設計のため、証拠金がゼロを下回る前に必ず強制決済される。

### 1.4 証拠金・損益計算式

#### 必要証拠金（JPY換算）

```
必要証拠金 = (1ロット × 1万通貨 × エントリーレート) ÷ レバレッジ

例: USD/JPY 150.00 で 2ロット、25倍レバレッジの場合
= (2 × 10,000 × 150.00) ÷ 25
= 3,000,000 ÷ 25
= 120,000 円
```

#### 含み損益（JPY換算）

```
【Buyポジション】
  含み損益 = (現在Bid - エントリーAsk) × ロット × 1万通貨 × 円換算レート

【Sellポジション】
  含み損益 = (エントリーBid - 現在Ask) × ロット × 1万通貨 × 円換算レート

例: USD/JPY Buy 1ロット、エントリー150.00、現在Bid150.30
= (150.30 - 150.00) × 1 × 10,000 × 1  ← USD/JPYは円建てなのでレート変換不要
= 0.30 × 10,000
= 3,000 円の含み益
```

#### pips損益換算（通貨ペア別）

| 通貨ペア | 1pip = | 1ロット(1万通貨)の1pip価値 |
|---------|--------|--------------------------|
| USD/JPY | 0.01円 | 100円 |
| EUR/JPY | 0.01円 | 100円 |
| EUR/USD | 0.0001ドル | 1ドル × USD/JPYレート |
| GBP/USD | 0.0001ドル | 1ドル × USD/JPYレート |

## 2. スリッページアルゴリズム詳細仕様

### 2.1 スリッページ発生条件

スリッページは **成行注文・逆指値注文・OCOの逆指値トリガー** に対してのみ適用する。指値注文には適用しない。

### 2.2 スリッページ計算アルゴリズム

```python
def calculate_slippage(order: Order, rate: Rate) -> float:
    """
    スリッページ量（pips）を計算して返す。

    算出要素:
    1. ボラティリティ係数（直近のレート変動速度）
    2. 経済指標係数（発表前後かどうか）
    3. 確率的ランダム要素（正規分布）
    """

    # ① ボラティリティ係数: 直近30秒のレート変動幅（pips）を取得
    recent_volatility_pips = redis.get_recent_volatility(order.symbol, seconds=30)
    # 変動幅が大きいほど係数が上がる（最大3.0倍）
    volatility_coeff = min(1.0 + (recent_volatility_pips / 10.0), 3.0)

    # ② 経済指標係数: 発表前後15分以内に高重要度指標があるか確認
    event_coeff = get_economic_event_coefficient(order.symbol)

    # ③ 基準スリッページ（通貨ペア別・正規分布で確率的に決定）
    #    平均: 0.5pips、標準偏差: 0.5pips（負の値は0にクランプ）
    base_slippage = max(0.0, random.gauss(mu=0.5, sigma=0.5))

    # 合成スリッページ（上限: 5pips）
    total_slippage = min(base_slippage * volatility_coeff * event_coeff, 5.0)

    return round(total_slippage, 3)


def get_economic_event_coefficient(symbol: str) -> float:
    """
    通貨ペアに関連する経済指標の発表前後15分以内なら係数を返す。
    """
    now = datetime.now(timezone.utc)
    window_start = now - timedelta(minutes=15)
    window_end   = now + timedelta(minutes=15)

    # 通貨ペアに関連する通貨コードを取得（例: USDJPY → ['USD', 'JPY']）
    currencies = get_currencies_for_symbol(symbol)

    # economic_events テーブルを参照
    events = db.query("""
        SELECT importance FROM economic_events
        WHERE currency = ANY(:currencies)
          AND scheduled_at BETWEEN :window_start AND :window_end
        ORDER BY importance DESC
        LIMIT 1
    """, currencies=currencies, window_start=window_start, window_end=window_end)

    if not events:
        return 1.0  # 指標なし: 係数1.0（変化なし）

    importance = events[0].importance
    coefficients = {
        'low':    1.2,   # 低重要度: 20%増
        'medium': 1.8,   # 中重要度: 80%増
        'high':   3.0,   # 高重要度（NFP等）: 3倍
    }
    return coefficients.get(importance, 1.0)


def apply_slippage(order: Order, rate: Rate, slippage_pips: float) -> float:
    """
    スリッページを考慮した実際の約定レートを算出する。
    スリッページは常に注文者に不利な方向へ発生する。
    """
    pip_unit = get_pip_unit(order.symbol)  # USD/JPY: 0.01、EUR/USD: 0.0001
    slippage_value = slippage_pips * pip_unit

    if order.side == 'buy':
        # Buy: 予定より高いAskで約定（不利方向）
        return rate.ask + slippage_value
    else:
        # Sell: 予定より低いBidで約定（不利方向）
        return rate.bid - slippage_value
```

| 通常相場（静穏） | 1.0 | 1.0 | 0〜1 pips |

## 3. 統計データ算出式・集計ロジック設計

### 3.1 全指標の計算定義

#### 勝率（Win Rate）

```
勝率 = 勝ちトレード数 ÷ 総トレード数

勝ちトレードの定義: net_pnl > 0
引き分け（net_pnl = 0）は総トレード数に含めるが勝ちとしない
```

#### 収益率 ROI（Return on Investment）

```
ROI = 累積純損益 ÷ 初期証拠金 × 100 (%)

累積純損益 = SUM(net_pnl) for all trades in period
初期証拠金 = virtual_accounts.initial_balance

月次ROI = 月内純損益 ÷ 月初残高 × 100 (%)
  ※ 月初残高 = 前月末時点の balance（DBの updated_at で判定）
```

#### プロフィットファクター（Profit Factor）

```
PF = 総利益 ÷ 総損失（絶対値）

総利益 = SUM(net_pnl) WHERE net_pnl > 0
総損失 = SUM(ABS(net_pnl)) WHERE net_pnl < 0

PF が計算不能のケース:
  - 損失トレードが0件 → PF = ∞（"∞" として表示）
  - 全てのトレードが損失 → PF = 0.00
```

#### 期待値（Expected Value per Trade）

```
期待値 = 勝率 × 平均利益 + 負け率 × 平均損失

平均利益 = AVG(net_pnl) WHERE net_pnl > 0
平均損失 = AVG(net_pnl) WHERE net_pnl < 0  ← 負の値
負け率   = 1 - 勝率

例:
  勝率 60%、平均利益 3,000円、平均損失 -2,000円
  期待値 = 0.6 × 3,000 + 0.4 × (-2,000)
         = 1,800 - 800
         = 1,000 円/トレード
```

#### リスクリワード比（Risk/Reward Ratio）

```
RRR = 平均利益 ÷ ABS(平均損失)

例: 平均利益 3,000円、平均損失 -2,000円
RRR = 3,000 ÷ 2,000 = 1.50（表示: 1:1.50）
```

#### 最大ドローダウン（Max Drawdown）

```
最大ドローダウンは「資産曲線の最高値から最安値への最大下落幅」を計算する。

アルゴリズム:
1. トレードを closed_at の昇順でソートし、累積残高の時系列を作成
2. 各時点の残高を走査し、「その時点までの最高残高（peak）」を記録
3. 各時点のドローダウン = (現在残高 - peak) ÷ peak × 100
4. 全期間の最小値（最大下落率）を最大ドローダウンとして返す

SQL実装例:
WITH running_balance AS (
    SELECT
        closed_at,
        SUM(net_pnl) OVER (ORDER BY closed_at) + :initial_balance AS balance
    FROM trades
    WHERE user_id = :user_id AND closed_at BETWEEN :from AND :to
),
with_peak AS (
    SELECT
        closed_at,
        balance,
        MAX(balance) OVER (ORDER BY closed_at) AS peak
    FROM running_balance
)
SELECT MIN((balance - peak) / peak * 100) AS max_drawdown
FROM with_peak;
```

#### 月次パフォーマンスの集計

```sql
-- 月次パフォーマンス集計クエリ
SELECT
    DATE_TRUNC('month', closed_at AT TIME ZONE 'UTC' AT TIME ZONE 'Asia/Tokyo') AS month_jst,
    COUNT(*)                                     AS total_trades,
    COUNT(*) FILTER (WHERE net_pnl > 0)          AS win_count,
    COUNT(*) FILTER (WHERE net_pnl <= 0)         AS loss_count,
    ROUND(
        COUNT(*) FILTER (WHERE net_pnl > 0)::numeric
        / NULLIF(COUNT(*), 0) * 100, 2
    )                                            AS win_rate_pct,
    SUM(net_pnl)                                 AS total_pnl_jpy,
    SUM(net_pnl) FILTER (WHERE net_pnl > 0)      AS gross_profit_jpy,
    ABS(SUM(net_pnl) FILTER (WHERE net_pnl < 0)) AS gross_loss_jpy,
    ROUND(
        SUM(net_pnl) FILTER (WHERE net_pnl > 0)
        / NULLIF(ABS(SUM(net_pnl) FILTER (WHERE net_pnl < 0)), 0), 2
    )                                            AS profit_factor,
    AVG(holding_duration_sec)                    AS avg_holding_sec
FROM trades
WHERE user_id = :user_id
GROUP BY 1
ORDER BY 1 DESC;
```

#### シャープレシオ（中級者向け・v1.1以降に対応）

```
シャープレシオ = (平均月次リターン - リスクフリーレート) ÷ 月次リターンの標準偏差

リスクフリーレート: 0%（仮想トレードのため）
計算対象: 最低12ヶ月分のデータが揃った場合のみ表示

実装上のNote:
  標準偏差 = 0 の場合（全月同一リターン）はシャープレシオ = ∞ のため非表示にする
```

### 3.2 成績サマリー API のクエリ設計

`GET /stats/summary` の内部クエリ構成：

```python
def get_stats_summary(user_id: str, from_dt: datetime, to_dt: datetime) -> dict:

    # 単一クエリで全指標を一括集計（パフォーマンス優先）
    result = db.query("""
        SELECT
            COUNT(*)                                         AS total_trades,
            COUNT(*) FILTER (WHERE net_pnl > 0)             AS win_count,
            COUNT(*) FILTER (WHERE net_pnl < 0)             AS loss_count,
            COALESCE(SUM(net_pnl), 0)                       AS total_pnl,
            COALESCE(SUM(net_pnl) FILTER (WHERE net_pnl > 0), 0) AS gross_profit,
            COALESCE(ABS(SUM(net_pnl) FILTER (WHERE net_pnl < 0)), 0) AS gross_loss,
            COALESCE(AVG(net_pnl) FILTER (WHERE net_pnl > 0), 0) AS avg_profit,
            COALESCE(AVG(net_pnl) FILTER (WHERE net_pnl < 0), 0) AS avg_loss,
            COALESCE(AVG(holding_duration_sec), 0)          AS avg_holding_sec,
            COALESCE(AVG(
                CASE WHEN net_pnl > 0 THEN ABS(net_pnl) ELSE NULL END
                / NULLIF(ABS(
                    CASE WHEN net_pnl < 0 THEN net_pnl ELSE NULL END
                ), 0)
            ), 0)                                           AS avg_rr_ratio
        FROM trades
        WHERE user_id = :user_id
          AND closed_at BETWEEN :from_dt AND :to_dt
    """, user_id=user_id, from_dt=from_dt, to_dt=to_dt)

    r = result[0]

    # 勝率
    win_rate = r.win_count / r.total_trades if r.total_trades > 0 else 0

    # ROI
    initial_balance = db.get_initial_balance(user_id)
    roi = r.total_pnl / initial_balance if initial_balance > 0 else 0

    # プロフィットファクター
    if r.gross_loss == 0 and r.gross_profit > 0:
        profit_factor = float('inf')
    elif r.gross_loss == 0:
        profit_factor = 0
    else:
        profit_factor = r.gross_profit / r.gross_loss

    # 期待値
    loss_rate = 1 - win_rate
    expected_value = (win_rate * r.avg_profit) + (loss_rate * r.avg_loss)

    # 最大ドローダウン（別クエリ: Window関数使用）
    max_drawdown = calc_max_drawdown(user_id, from_dt, to_dt, initial_balance)

    return {
        "period": {"from": from_dt.isoformat(), "to": to_dt.isoformat()},
        "total_trades": r.total_trades,
        "win_count": r.win_count,
        "loss_count": r.loss_count,
        "win_rate": round(win_rate, 4),
        "total_pnl_jpy": float(r.total_pnl),
        "roi": round(roi, 4),
        "profit_factor": round(profit_factor, 2) if profit_factor != float('inf') else None,
        "max_drawdown": round(max_drawdown, 4),
        "expected_value_jpy": round(float(expected_value), 0),
        "average_rr_ratio": round(float(r.avg_rr_ratio), 2),
        "average_holding_sec": int(r.avg_holding_sec)
    }
```

## 4. タイムゾーン処理詳細

### 4.1 タイムゾーン変換ルール

| 処理 | ルール |
|------|--------|
| DB保存 | 全タイムスタンプを UTC（TIMESTAMPTZ型）で保存 |
| API レスポンス | UTC の ISO 8601 形式で返却（例: `2026-03-20T12:00:00Z`） |
| フロントエンド表示 | `date-fns-tz` を使用してJSTに変換して表示 |
| 月次集計の区切り | `DATE_TRUNC('month', closed_at AT TIME ZONE 'Asia/Tokyo')` でJST月初を基準 |
| 日次統計の区切り | JST 00:00（= UTC 前日 15:00）を1日の区切りとする |

### 4.2 サマータイム自動換算

経済指標カレンダーの発表時刻表示において、米国・欧州のサマータイムを自動換算する。

```python
from zoneinfo import ZoneInfo

def convert_to_jst_display(utc_dt: datetime) -> str:
    """UTCのdatetimeをJST表示用文字列に変換"""
    jst = ZoneInfo("Asia/Tokyo")
    jst_dt = utc_dt.astimezone(jst)
    return jst_dt.strftime("%Y/%m/%d %H:%M JST")

# 経済指標取得側（外部APIのレスポンスがETまたはCETの場合）
def normalize_event_time(event_time_str: str, source_timezone: str) -> datetime:
    """外部APIのタイムゾーン表記をUTCに正規化してDBに保存"""
    source_tz = ZoneInfo(source_timezone)  # 例: "America/New_York"
    local_dt = datetime.fromisoformat(event_time_str).replace(tzinfo=source_tz)
    return local_dt.astimezone(timezone.utc)
```
