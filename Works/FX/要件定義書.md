## 1. プロジェクト概要

### 1.1 背景・目的

FX（外国為替証拠金取引）は、初級〜中級者にとって実際の資金を使ったトレードにはリスクが伴う。本アプリは、リアルな取引環境を仮想的に再現することで、資金リスクなく安全にトレードスキルを習得・向上させる場を提供する。

### 1.2 プロジェクトスコープ

| 項目 | 内容 |
|------|------|
| 対象ユーザー | FX超初心者〜中級者（基礎知識ゼロから実践力を磨きたい方まで） |
| プラットフォーム | Webアプリケーション（PC・スマートフォンのブラウザ） |
| 提供形態 | SaaS（ブラウザからアクセス） |
| 言語 | 日本語（初期リリース） |
| タイムゾーン | JST（日本標準時、UTC+9）を基準とする。チャートの日足区切り・経済指標表示はすべてJSTで統一。 |
| 運用品質 | 本格運用（Production-grade）を前提とする。学習用のデモシステムではなく、実際のFX取引に近いリアリティを追求する。 |

## 3. ユーザー要件

### 3.1 ターゲットユーザーのペルソナ

**ペルソナA（超初心者）**
- 年齢: 20〜35歳
- FX歴: なし〜1ヶ月
- 課題: FXの仕組みが全くわからない、用語が難しい、いきなりお金を使うのが怖い
- ニーズ: リスクなく基礎から体験しながら学びたい

**ペルソナB（初級〜中級者：メインターゲット）**
- 年齢: 25〜40歳
- FX歴: 3ヶ月〜2年
- 課題: チャート読みが苦手、エントリータイミングが掴めない、損切りができない、ファンダメンタルの読み方がわからない
- ニーズ: 実際の相場データを使って安全にトレードの腕を磨きたい

### 3.2 ユーザーストーリー

| ID | ユーザーストーリー | 優先度 |
|----|--------------------|--------|
| US-01 | 仮想資金でBuy/Sellの注文を出し、損益をリアルタイムに確認したい | 最高 |
| US-02 | 実際の為替レートを参照してリアルな相場環境で練習したい | 最高 |
| US-03 | ローソク足チャートとテクニカル指標を見ながらトレードしたい | 高 |
| US-04 | レバレッジとロスカットの仕組みを体験・理解したい | 高 |
| US-05 | 過去のトレード履歴・勝率・損益をグラフで振り返りたい | 高 |
| US-06 | テクニカル分析（移動平均・RSI・MACD等）の使い方を学びたい | 中 |
| US-07 | チャートパターンやインジケーターの解説を読みたい | 中 |
| US-08 | 経済指標（雇用統計・CPI・政策金利等）がレートに与える影響をファンダメンタル視点で学びたい | 中 |
| US-09 | エリオット波動理論をチャート上で視覚的に学び、波のカウントを練習したい | 中 |
| US-10 | OCO注文など複合的な注文タイプを使いこなせるようになりたい | 高 |
| US-11 | 自分のトレードの収益率（ROI）や月次パフォーマンスを数値で把握したい | 高 |

## 4. 機能要件

### 4.1 機能一覧

#### 4.1.1 認証・アカウント管理

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-001 | ユーザー登録 | メールアドレス＋パスワードで新規登録 |
| F-002 | ログイン / ログアウト | 認証情報によるセッション管理 |
| F-003 | プロフィール設定 | ユーザー名・アバター変更 |
| F-004 | 仮想資金リセット | 練習用資金を初期値に戻す |

#### 4.1.2 リアルタイムレート表示

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-101 | 為替レート取得 | 外部API（例: ExchangeRate API / OANDA）からリアルタイムレートを取得 |
| F-102 | 通貨ペア選択 | USD/JPY・EUR/JPY・EUR/USD・GBP/USD 等の主要ペアを選択 |
| F-103 | スプレッド表示 | Bid/Askの差（スプレッド）をリアルに反映 |

#### 4.1.3 ローソク足チャート

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-201 | ローソク足チャート表示 | 1分・5分・15分・1時間・4時間・日足の時間軸切り替え |
| F-202 | テクニカルインジケーター | 移動平均線（SMA/EMA）・RSI・MACD・ボリンジャーバンドを表示 |
| F-203 | インジケーター解説 | 各インジケーターのホバー時に簡易解説を表示 |
| F-204 | チャートズーム / スクロール | 時間軸方向のズームおよびスクロール操作 |

#### 4.1.4 模擬トレード

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-301 | 成行注文（Buy/Sell） | 現在レートで即時約定 |
| F-302 | 指値注文（Limit Order） | 指定レートよりも有利なレートになったときに自動約定（例: 現在より安い価格でBuy） |
| F-303 | 逆指値注文（Stop Order） | 指定レートに達した時点で成行注文を発動（ブレイクアウト戦略等に利用） |
| F-304 | OCO注文（One Cancels the Other） | 指値と逆指値を同時に発注し、一方が約定したら他方を自動キャンセル |
| F-305 | IFD注文（If Done） | 最初の注文が約定したら、自動的に次の注文（SL/TP）を発注 |
| F-306 | IFO注文（IFD + OCO） | IFDとOCOを組み合わせ、エントリー後にSL・TPを同時設定 |
| F-307 | ポジション管理 | 保有中ポジションの一覧表示・個別決済・一括決済 |
| F-308 | ロット数・レバレッジ設定 | 取引ロット数とレバレッジ倍率の設定 |
| F-309 | 損切り / 利確ライン設定 | SL（ストップロス）・TP（テイクプロフィット）の設定 |
| F-310 | 仮想証拠金残高管理 | 取引ごとの証拠金・有効証拠金・維持率をリアルタイム反映 |
| F-311 | 注文タイプ解説パネル | 各注文タイプの違いを初心者向けにわかりやすく説明するポップアップ |
| F-312 | スリッページ再現 | 成行注文・逆指値注文の約定時に、相場のボラティリティに応じたスリッページ（最大数pips）を確率的に発生させ、リアルな約定体験を再現する |
| F-313 | サーバーサイド注文マッチング | OCO/IFD/IFO等の未約定注文の監視・約定処理はすべてサーバー側で実行する。クライアント（ブラウザ）が切断中でも注文処理は継続される |

#### 4.1.5 損益シミュレーション

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-401 | ロスカットシミュレーション | 証拠金維持率が一定水準を下回った際の強制決済を再現 |
| F-402 | レバレッジ別損益試算 | レバレッジを変えたときの損益をリアルタイム表示 |
| F-403 | pip計算機 | ロット数・通貨ペアに基づくpip単価を計算・表示 |

#### 4.1.6 成績・統計管理

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-501 | トレード履歴一覧 | 全トレードの日時・通貨ペア・損益・勝敗・保有時間を一覧表示 |
| F-502 | 勝率・損益グラフ | 期間別の勝率・累積損益をグラフで可視化 |
| F-503 | リスクリワード分析 | 平均リスク/リワード比率の算出・表示 |
| F-504 | 最大ドローダウン表示 | 最大損失幅（ドローダウン）の可視化 |
| F-505 | CSVエクスポート | トレード履歴のCSVダウンロード |
| F-506 | 収益率（ROI）計算 | 初期証拠金に対する累積損益の割合を算出・表示（計算式: 収益率 = 累積損益 ÷ 初期証拠金 × 100%） |
| F-507 | 月次・週次パフォーマンスレポート | 月・週ごとのトレード件数・勝率・損益・収益率を集計しレポート表示 |
| F-508 | 期待値計算 | 1トレードあたりの期待損益を算出（計算式: 期待値 = 勝率 × 平均利益 − 負け率 × 平均損失） |
| F-509 | プロフィットファクター | 総利益 ÷ 総損失で算出するトレード品質指標を表示 |
| F-510 | パフォーマンスサマリー | ダッシュボードに主要指標（勝率・収益率・PF・ドローダウン）を一目でわかるカード形式で表示 |

#### 4.1.7 ファンダメンタル分析

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-601 | 経済指標カレンダー | 雇用統計・CPI・GDP・政策金利等の発表スケジュールを表示。発表時刻にチャート上でマーカーを表示 |
| F-602 | 経済指標解説 | 各指標の意味・為替への影響度・過去の反応事例を解説 |

| F-605 | ファンダメンタル×チャート比較 | 経済指標発表前後のレート変動をチャートで可視化して学習 |

#### 4.1.8 エリオット波動学習

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-701 | エリオット波動オーバーレイ | チャート上に波動ラベル（1〜5波・A〜C波）を手動で描画・注釈できるツール |

## 5. 非機能要件

### 5.1 性能要件

| 項目 | 要件 |
|------|------|
| レート更新頻度 | 1秒〜5秒ごとにリアルタイム更新 |
| 画面表示速度 | 初期ロード3秒以内（一般的なブロードバンド環境） |
| 同時接続ユーザー数 | 初期リリース時: 100ユーザー以上に対応 |
| チャート描画 | データ取得から描画まで1秒以内 |

### 5.2 セキュリティ要件

| 項目 | 要件 |
|------|------|
| 通信の暗号化 | HTTPS（TLS 1.2以上）を必須とする |
| 認証 | JWTまたはセッションベース認証 |
| パスワード管理 | bcrypt等によるハッシュ化保存 |
| 入力バリデーション | XSS・SQLインジェクション対策を実施 |

### 5.3 可用性・信頼性要件

| 項目 | 要件 |
|------|------|
| 稼働率 | 99%以上（月次） |
| バックアップ | ユーザーデータを日次バックアップ |
| 障害復旧 | 障害発生から4時間以内に復旧 |

### 5.4 ユーザビリティ要件

| 項目 | 要件 |
|------|------|
| レスポンシブ対応 | PC・タブレット・スマートフォンに対応 |
| ブラウザ対応 | Chrome / Firefox / Safari / Edge の最新版 |
| アクセシビリティ | WCAG 2.1 レベルAA準拠を目標 |

### 5.5 保守性要件

| 項目 | 要件 |
|------|------|
| ログ管理 | アプリケーションログ・エラーログの記録 |
| 設定の外部化 | APIキー・DB接続情報は環境変数で管理 |
| コードの可読性 | コーディング規約に基づいたコメント・命名 |

### 5.6 タイムゾーン要件

| 項目 | 要件 |
|------|------|
| 基準タイムゾーン | JST（日本標準時 UTC+9）を全画面・全機能で統一使用 |
| チャートの日足区切り | JST 00:00 を1日の区切りとする（NYクローズ基準ではなく日本時間基準） |
| 経済指標カレンダー | 発表時刻はJSTに変換して表示。サマータイム（米国・欧州）の自動換算を行う |
| DB保存形式 | タイムスタンプはUTCで保存し、表示時にJSTへ変換する |

### 5.7 オフライン・通信断時の挙動要件

| 項目 | 要件 |
|------|------|
| 切断検知 | WebSocket接続が切れた場合、3秒以内にフロントエンドが検知し、「接続が切れています」のオーバーレイを全画面に表示する |
| 損益表示の凍結 | 通信断中は損益・レートの表示を最後の値で凍結し、誤った情報を表示しない |
| 注文処理の継続 | 未約定注文（指値・逆指値・OCO等）の監視・約定処理はサーバー側で継続。クライアント切断の影響を受けない |
| 自動再接続 | 切断後、指数バックオフ方式（1秒→2秒→4秒→最大30秒）で自動再接続を試みる |
| 再接続後の同期 | 再接続成功時に、最新レート・保有ポジションの損益・切断中に約定した注文結果をサーバーから一括取得し画面を更新する |
| ユーザー通知 | 切断・再接続・同期完了の各タイミングでトースト通知（画面端のポップアップ）を表示する |

### 5.8 スリッページ要件

| 項目 | 要件 |
|------|------|
| 対象注文 | 成行注文（F-301）・逆指値注文（F-303）・OCOの逆指値トリガー時に適用 |
| スリッページ幅 | 通常相場: 0〜2pips、ボラティリティ高（経済指標発表前後）: 1〜5pips を確率的に発生させる |
| 実装方式 | ランダム要素（正規分布）にレート変動速度を加味したアルゴリズムで算出 |
| 学習への活用 | 約定画面でスリッページが発生した場合、その旨と発生原因（急変動等）をポップアップで表示し、学習体験として活用する |
| 指値注文への適用 | 指値注文はスリッページなし（有利方向への約定のため実際のFXと同様に適用しない） |

### 5.9 本格運用品質要件

| 項目 | 要件 |
|------|------|
| 注文処理の整合性 | 注文の約定・キャンセルはACID特性を持つDBトランザクションで処理し、二重約定・データ不整合を防止する |
| レート精度 | 小数点第3位以上（USD/JPY: 0.001円精度）のレートを扱い、pip計算・損益計算に反映する |
| 監査ログ | 全注文操作（発注・約定・キャンセル・決済）をタイムスタンプ付きで記録し、後から追跡可能にする |
| 負荷対策 | 経済指標発表時など急激なリクエスト増加に対し、サーバー側でレートキャッシュとキュー処理を用いて安定稼働を維持する |
| データ保持期間 | ユーザーのトレード履歴は最低2年間保持する |

```
    │
    ▼

    ├── [PostgreSQL DB]
    └── [外部為替レートAPI]
```

## 7. 制約条件

| 項目 | 内容 |
|------|------|
| 法的制約 | 仮想トレードのみ提供。実際の金融商品取引には該当しないことを明記 |
| 外部API依存 | リアルタイムレートは外部APIの稼働状況に依存。APIダウン時はキャッシュされた直前レートを表示し、ユーザーに通知する |
| 免責事項 | 本アプリは学習目的のみ。実際の投資判断に使用しないことをユーザーに周知 |
| タイムゾーン固定 | タイムゾーンはJST固定。多言語・多地域展開は初期リリースのスコープ外とする |
| スリッページの限界 | スリッページはアルゴリズムによる近似再現であり、実際の市場における約定と完全に一致するものではない |
| ヒストリカルデータ | 波動カウント練習（F-703）に使用する過去データは、外部API（Alpha Vantage等）から取得・DB保存する。取得可能期間は利用するAPIのプランに依存する |

| AC-02 | 実際の為替レートをもとにしたチャートが表示される |
| AC-03 | RSI・移動平均線・MACDが正しくチャートに描画される |
| AC-04 | ロスカット条件を満たした場合、強制決済が実行される |
| AC-05 | トレード履歴が保存され、勝率・損益グラフが正しく表示される |
| AC-06 | PCおよびスマートフォンのブラウザで問題なく操作できる |
| AC-07 | HTTPS接続が確立されており、パスワードがハッシュ化されている |
| AC-08 | 成行注文・逆指値注文の約定時にスリッページが確率的に発生し、約定画面に表示される |
| AC-09 | WebSocket切断時に「接続が切れています」のオーバーレイが3秒以内に表示され、再接続後に損益・注文状態が正しく同期される |
| AC-10 | チャートの日足区切り・経済指標の時刻表示がすべてJST基準で正しく表示される |
| AC-11 | 全注文操作が監査ログに記録され、DBトランザクションにより二重約定が発生しないことが確認できる |

## 10. 用語定義

超初心者〜中級者を対象に、FXに登場する用語を体系的にまとめる。

### 10.1 FXの基本

| 用語 | 説明 |
|------|------|
| FX | Foreign Exchange（外国為替証拠金取引）の略。2つの通貨を交換・売買して差益を狙う取引。 |
| 通貨ペア | 取引対象となる2つの通貨の組み合わせ。例: USD/JPY（米ドル / 日本円）。左側を「基軸通貨」、右側を「決済通貨」という。 |
| レート（為替レート） | 1つの通貨を別の通貨に換えるときの交換比率。例: USD/JPY = 150.00 なら 1ドル = 150円。 |
| Bid（ビッド） | 市場があなたから通貨を買い取る価格（=売り注文を出すときに適用されるレート）。 |
| Ask（アスク） | 市場があなたに通貨を売る価格（=買い注文を出すときに適用されるレート）。通常 Bid より高い。 |
| スプレッド | BidとAskの差額。実質的な取引コスト。例: Ask 150.02 − Bid 150.00 = 0.02円のスプレッド。 |
| pips（ピップス） | 為替レートの最小変動単位。USD/JPYなら0.01円（小数点第2位）、EUR/USDなら0.0001ドル（小数点第4位）が1pips。 |
| ロット | 取引量の単位。1ロット = 1万通貨（FX業者によって異なる場合あり）。 |
| 証拠金 | トレードに必要な担保金（デポジット）。レバレッジを使って少ない証拠金で大きな取引ができる。 |
| レバレッジ | 証拠金の何倍まで取引できるかの倍率。例: 25倍レバレッジなら10万円の証拠金で250万円分の取引が可能。 |
| 有効証拠金 | 証拠金 ± 含み損益。現在使える資金の合計。 |
| 証拠金維持率 | 有効証拠金 ÷ 必要証拠金 × 100%。この比率が一定水準（業者によって異なる）を下回るとロスカットが発動する。 |
| ロスカット | 証拠金維持率が一定以下になったときに、強制的に全ポジションを決済される仕組み。損失拡大を防ぐための安全装置。 |
| 追証（おいしょう） | ロスカット前に不足した証拠金を追加入金しなければならない状態。業者によっては追証が発生する。 |

### 10.2 注文タイプ

| 用語 | 説明 |
|------|------|
| 成行注文（Market Order） | 注文した瞬間の相場レートで即時約定する注文方法。確実に約定するが、スリッページが発生することがある。 |
| 指値注文（Limit Order） | 「このレートになったら買う/売る」と事前に指定する注文。現在より有利なレートで約定する。Buyなら現在より安い価格、Sellなら現在より高い価格を指定。 |
| 逆指値注文（Stop Order） | 「このレートを超えたら成行注文を出す」という条件付き注文。ブレイクアウト戦略や損切りに使う。 |
| OCO注文（One Cancels the Other） | 指値注文と逆指値注文を同時に発注し、どちらかが約定した瞬間にもう一方が自動でキャンセルされる注文。利確と損切りを同時に設定できる。 |
| IFD注文（If Done） | 「最初の注文が約定したら、次の注文を自動発注する」という2段階注文。例: 成行でエントリー → 約定後に自動でTP注文を出す。 |
| IFO注文（If Done + OCO） | IFDとOCOを組み合わせた注文。エントリー後に利確・損切りを同時に自動設定できる。実践的なトレードに多用される。 |
| スリッページ | 注文レートと実際に約定したレートのズレ。相場が急変動するときに起こりやすい。 |
| 約定（やくじょう） | 注文が成立すること。 |
| 未約定（みやくじょう） | 注文を出したが、まだ約定していない状態。 |

### 10.3 ポジションと損益

| 用語 | 説明 |
|------|------|
| ポジション | 現在保有している未決済の取引。「ポジションを持つ」＝エントリーして保有中の状態。 |
| ロングポジション（買いポジション） | 通貨を買った状態。レートが上昇すれば利益、下落すれば損失になる。 |
| ショートポジション（売りポジション） | 通貨を売った状態（最初に売って後で買い戻す）。レートが下落すれば利益、上昇すれば損失になる。 |
| エントリー | 取引を開始すること（ポジションを持つこと）。 |
| 決済（クローズ） | 保有ポジションを反対売買で終わらせること。ここで初めて損益が確定する。 |
| 含み損益（ふくみそんえき） | 未決済ポジションの評価損益。まだ確定していない損益。 |
| 確定損益 | 決済した後に確定した損益。 |
| SL（ストップロス） | 損切りラインのこと。あらかじめ「このレートになったら損切りする」と設定しておく。 |
| TP（テイクプロフィット） | 利確ライン。「このレートになったら利益確定する」と設定しておく。 |
| 損切り（ロスカット注文） | 損失を小さくするために意図的に決済すること。SL注文とは別に手動でも行える。 |
| 利確（りかく） | 利益が出ているポジションを決済して利益を確定させること。 |
| スワップポイント | 異なる金利を持つ通貨ペアを保有し続けたときに、毎日受け取り or 支払いが発生する金利差調整分。 |

### 10.4 チャートとテクニカル分析

| 用語 | 説明 |
|------|------|
| ローソク足 | 一定時間の始値・高値・安値・終値を1本のロウソク形状で表したチャート。色（陽線・陰線）で上昇・下落を示す。 |
| 陽線（ようせん） | 終値 > 始値のローソク足。価格が上昇した時間帯を示す。一般的に白または緑で表示。 |
| 陰線（いんせん） | 終値 < 始値のローソク足。価格が下落した時間帯を示す。一般的に黒または赤で表示。 |
| ヒゲ（上ヒゲ・下ヒゲ） | ローソク足の胴体から上下に伸びる細い線。その時間帯の最高値・最安値を示す。 |
| 時間軸（タイムフレーム） | チャートの1本のローソク足が表す時間帯。1分足・5分足・1時間足・4時間足・日足など。 |
| トレンド | 価格が一定方向に動き続ける状態。上昇トレンド・下降トレンド・レンジ（横ばい）の3種類。 |
| サポートライン（支持線） | 価格が何度も跳ね返された下値の水平ライン。買い圧力が強い水準を示す。 |
| レジスタンスライン（抵抗線） | 価格が何度も跳ね返された上値の水平ライン。売り圧力が強い水準を示す。 |
| ブレイクアウト | サポートやレジスタンスを価格が突き抜けること。トレンド転換やトレンド加速のサインとなることが多い。 |
| 移動平均線（SMA・EMA） | 一定期間の終値の平均を線で結んだもの。SMAは単純平均、EMAは直近に重みを置いた加重平均。 |
| RSI（相対力指数） | 0〜100の範囲で売られすぎ・買われすぎを示す指標。一般的に70以上で買われすぎ、30以下で売られすぎ。 |
| MACD | 2本の移動平均線の差（MACDライン）とそのシグナル線を使ったトレンド系インジケーター。交差がエントリーサインとなる。 |
| ボリンジャーバンド | 移動平均線を中心に標準偏差で上下の帯（バンド）を描いた指標。バンドの幅でボラティリティを把握する。 |
| フィボナッチリトレースメント | 価格の押し目・戻りの目安となるレベル（23.6%・38.2%・61.8%等）を自動計算するツール。エリオット波動と組み合わせて使われる。 |
| ゴールデンクロス | 短期移動平均線が長期移動平均線を下から上に抜ける現象。上昇サインとして扱われることが多い。 |
| デッドクロス | 短期移動平均線が長期移動平均線を上から下に抜ける現象。下落サインとして扱われることが多い。 |

### 10.5 エリオット波動

| 用語 | 説明 |
|------|------|
| エリオット波動 | ラルフ・ネルソン・エリオットが提唱した波動理論。相場は「5波の推進波 + 3波の修正波」のパターンを繰り返すとする理論。 |
| 推進波（インパルス波） | トレンド方向に動く5つの波（第1波〜第5波）。第1・3・5波がトレンド方向、第2・4波が押し目・戻り。 |
| 修正波 | 推進波の後に発生するトレンドと逆方向の調整（A・B・C波の3波構成）。 |
| 第3波 | 通常最も強く長い推進波。最も利益を狙いやすい波とされる。 |
| ジグザグ | 修正波の一種（A-B-C）。強い一方向への調整パターン。 |
| フラット | 修正波の一種。A波とC波がほぼ同じ長さで横ばいに近い調整をするパターン。 |
| トライアングル | 修正波の一種。価格がだんだん収縮しながらトライアングル形状を形成するパターン。ブレイクアウトの前触れになることが多い。 |
| 波動カウント | チャート上の波を数えてどの波動にいるかを分析する作業。エリオット波動分析の基本作業。 |

### 10.6 ファンダメンタル分析

| 用語 | 説明 |
|------|------|
| ファンダメンタル分析 | 経済指標・金融政策・政治情勢など経済の根本要因を分析してレートの方向性を予測する手法。テクニカル分析と対をなす。 |
| 経済指標 | 各国が定期的に発表する経済の状態を示す統計データ。雇用・物価・GDP・貿易収支などがある。 |
| CPI（消費者物価指数） | 消費者が購入する商品・サービスの価格変動を示す指標。インフレの状況を反映し、金融政策に大きく影響する。 |
| 雇用統計（NFP） | 米国の非農業部門雇用者数（Non-Farm Payrolls）。毎月第1金曜日に発表され、ドル相場を大きく動かす最重要指標のひとつ。 |
| GDP（国内総生産） | 一定期間内に国内で生産された財・サービスの総額。経済規模・成長率を示す最も基本的な経済指標。 |
| 金融政策 | 中央銀行が金利や通貨量を調整することで経済・インフレをコントロールする政策。 |
| 政策金利 | 中央銀行が設定する基準となる金利。金利が上がると通貨が買われやすく、下がると売られやすい傾向がある。 |
| FRB（米連邦準備制度理事会） | アメリカの中央銀行。FOMC会合で政策金利を決定し、ドルと世界経済に大きな影響を与える。 |
| FOMC | Federal Open Market Committee（連邦公開市場委員会）。FRBが年8回開催する金融政策決定会合。 |
| ECB（欧州中央銀行） | ユーロ圏の金融政策を担う中央銀行。ユーロの価値に直接影響する。 |
| 日銀（BOJ） | 日本銀行（Bank of Japan）。円の金融政策を担い、介入によって円相場に影響を与えることがある。 |
| 為替介入 | 政府や中央銀行が自国通貨の急激な変動を抑えるために直接市場で売買を行うこと。 |
| リスクオン | 投資家が積極的にリスク資産（株・高金利通貨）を買う局面。円やスイスフランなど安全資産が売られやすい。 |
| リスクオフ | 不安心理から投資家が安全資産（円・スイスフラン・金）に資金を逃がす局面。 |

### 10.7 成績・パフォーマンス指標

| 用語 | 説明 |
|------|------|
| 勝率 | 全トレード数に対する勝ちトレード数の割合。例: 10回中6勝なら勝率60%。勝率だけでは収益性は判断できない。 |
| 収益率（ROI） | 初期証拠金に対する累積損益の割合。計算式: 収益率 = 累積損益 ÷ 初期証拠金 × 100%。例: 10万円で1万円の利益 → ROI 10%。 |
| リスクリワード比（RRR） | 1トレードあたりの損失リスクと利益目標の比率。例: 損切り10pips・利確30pips → RRR 1:3。 |
| 期待値 | 1トレードあたりに期待できる平均損益。計算式: 期待値 = 勝率 × 平均利益 − 負け率 × 平均損失。プラスであれば長期的に利益が出る戦略とされる。 |
| プロフィットファクター（PF） | 総利益 ÷ 総損失で計算されるトレード品質の指標。1.0以上で利益超過、2.0以上なら優秀とされる。 |
| ドローダウン | 資産の高値から低値への下落幅。最大ドローダウンが小さいほどリスクが低いとされる。 |
| 月次収益率 | 月ごとの損益 ÷ 月初証拠金 × 100%。月単位でのパフォーマンスを測る指標。 |
| シャープレシオ | リスクあたりの収益率を示す指標。値が高いほど効率よく利益を上げている戦略とされる（中級者向け指標）。 |

### 10.8 システム・運用用語

| 用語 | 説明 |
|------|------|
| JST（日本標準時） | Japan Standard Time（UTC+9）。本アプリの全時刻表示の基準タイムゾーン。 |
| サマータイム | 夏季に時計を1時間進める制度（米国・欧州）。経済指標の発表時刻がJSTで変わるため、アプリが自動換算して表示する。 |
| スリッページ | 注文レートと実際の約定レートのズレ。成行注文・逆指値注文で発生しやすく、相場が急変動するときほど大きくなる。本アプリでは意図的に再現し、リアルなトレード体験を提供する。 |
| WebSocket | サーバーとブラウザが常時接続を保ち、リアルタイムでデータを双方向に送受信する通信技術。レートや損益のリアルタイム更新に使用する。 |
| 指数バックオフ | 再接続を試みる間隔を1秒→2秒→4秒と指数的に延ばしていく方式。サーバーへの負荷集中を防ぐ標準的な再接続アルゴリズム。 |
| サーバーサイド処理 | 注文の約定判定などの重要なロジックをサーバー側で行うこと。クライアント（ブラウザ）が切断・改ざんされても正確な処理が保証される。 |
| ACIDトランザクション | データベースの処理において、原子性・一貫性・独立性・耐久性を保証する仕組み。二重約定や残高不整合を防ぐために使用する。 |
| 監査ログ | 誰がいつどのような操作を行ったかを記録したログ。障害調査・不正検知・トレード履歴の正確性担保に使用する。 |
| レートキャッシュ | 外部APIから取得した最新レートをサーバーに一時保存しておく仕組み。API障害時のフォールバックや、多ユーザーへの効率的なブロードキャストに使用する。 |
| ブロードキャスト | 1つのサーバーから全接続クライアントへ同時にデータを送信すること。レート更新を全ユーザーに一斉配信する際に使用する。 |
